# 项目Git分支管理规范

## 推荐学习文档
[菜鸟Git教程](https://liaoxuefeng.com/books/git/introduction/index.html)（快速掌握Git基础操作）


## 分支概览
| 分支名   | 来源分支 | 核心用途                     |
|----------|----------|------------------------------|
| master   | -        | 线上稳定版本分支             |
| develop  | master   | 日常开发主分支               |
| feature  | develop  | 单个功能开发分支             |
| test     | develop  | 集成测试环境分支             |
| hotfix   | master   | 线上问题紧急修复分支         |
| release  | develop  | 预发布版本准备分支           |


## 各分支详细说明
### 1. master（主分支）
- **来源**：项目初始化分支（无上游分支）
- **包含内容**：仅**底座代码**（稳定版本）
- **操作规则**：
    - 禁止直接向master提交代码


### 2. develop（开发分支）
- **来源**：从`master`分支签出
- **包含内容**：`底座代码` + `公共组件代码`
- **操作规则**：
    - 日常开发的主分支，保持可运行状态
    - 所有`feature`分支需从develop签出


### 3. feature（特性分支）
- **来源**：从`develop`签出（命名示例：`feature_SAC-0004_20251127`）
- **包含内容**：`底座代码` + `公共组件代码` + `单个功能的业务代码`
- **操作规则**：
    - 一个feature对应一个独立功能
    - 开发完成后合并到`test`


### 4. test（测试分支）
- **来源**：从`develop`分支签出
- **包含内容**：`底座代码` + `公共组件代码` + `所有已完成的功能代码`
- **操作规则**：
    - 持续合并已完成的`feature`分支
    - 用于测试环境部署，供业务人员验证功能


### 5. hotfix（紧急修复分支）
- **来源**：从`master`签出
- **包含内容**：`底座代码` + 对应的**紧急修复代码**
- **操作规则**：
    - 修复线上突发问题


### 6. release（发布分支）
- **来源**：从`develop`签出
- **包含内容**：`底座代码` + `公共组件代码` + `所有已完成的功能代码`
- **操作规则**：
    - 用于预发布环境的最终验证（性能、兼容性等）
